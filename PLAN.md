# Personal Exercise Trainer — Plan

Owner: Tal. Date: 2026-09-08. Status: phases 0-1 built 2026-09-08; CLI (phase 2) next.

## 1. What it is

A trainer you talk to. It knows your history, tells you what to do today, records what you
actually did, adjusts next week, and nags you when you skip. Every byte of data lives as plain
files in a private GitHub repo (`talgiladi/personal-trainer`) — no database, no third-party
fitness service, fully greppable, fully yours.

The "brain" is Claude. The repo is the memory. A thin CLI does the arithmetic Claude should not
do by hand (volume, progression, streaks, charts). Voice is a front-end option, not a core part.

## 2. Facts (from Tal, 2026-09-08)

- Trains **every day**. Main targets: **strength + cardio**.
- Home only: dumbbells, bands, bodyweight. Cardio is HIIT / Tabata at home.
- Exercise names dictated in **English**.
- **No** body-weight or heart-rate tracking.
- "Speak with me" = conversational in the Claude app (desktop/mobile), voice via the app's
  voice mode. No custom speech stack.
- One user, private repo, no third-party fitness service.
- Units: kg, km, min. Timezone Asia/Jerusalem.
- This repo is standalone. It shares nothing with work repos - no global CLAUDE.md, no memory.

## 3. Architecture

```
 you (chat / voice)
      │
      ▼
 Claude (Claude Code or Claude app) ── reads CLAUDE.md + skills in the repo
      │            │
      │            └── runs `trainer` CLI for math/validation/charts
      ▼
 GitHub repo  (data/*.yaml, logs/*.md, plans/*.yaml)
      │
      └── GitHub Actions: validate on push, weekly summary, streak/nag reminders
```

Three components:

1. **Repo as the system of record** — all state is files; every workout is a commit. History is
   `git log`. Rollback is `git revert`.
2. **Claude as the trainer** — a `CLAUDE.md` persona + three skills (`/workout`, `/log`,
   `/review`). It talks, plans, and writes files. It never invents numbers: it calls the CLI.
3. **`trainer` CLI** (.NET 8 console, single-file publish; or `py` if you want it in an hour) —
   `validate`, `next`, `log`, `stats`, `chart`, `progress`. Deterministic, unit-tested.

Why not an app with a DB: you would build a UI nobody uses. Chat + files gets a working trainer
in a weekend and keeps every design decision reversible.

## 4. Data model (files)

```
personal-trainer/            (local clone: C:SERSTALGILADIONEDRIVE
EPOSPERSONAL-TRAINER)
  CLAUDE.md                     trainer persona, rules, how to talk to me
  .claude/skills/
     workout/SKILL.md           "what do I do today" → reads plan + history, produces session
     log/SKILL.md               "I did X" → structured log entry + commit
     review/SKILL.md            weekly review → adjust plan, write summary
  profile.yaml                  age, height, goals, injuries, equipment, schedule, units
  exercises/
     catalogue.yaml             name, muscle groups, equipment, unit (reps|time|distance), aliases (he/en)
  plans/
     2026-09-current.yaml       the active programme: weeks × days × exercises × targets
     archive/                   old programmes
  logs/
     2026/09/2026-09-08.yaml    one file per session: exercises, sets, reps, load, RPE, notes, duration
  reports/
     weekly/2026-W37.md         generated by /review: volume, PRs, adherence, next-week changes
  charts/                       PNG/SVG rendered by the CLI, committed for GitHub viewing
  tools/trainer/                the CLI (+ tests)
  .github/workflows/
     validate.yml               schema-check every yaml on push
     weekly.yml                 Monday 07:00: stats + chart + open an issue "review week 37"
     nag.yml                    daily: if no log in N days, open/update a "you skipped" issue
  schemas/*.json                JSON Schema for every yaml type
```

Session log shape (the one thing everything else derives from):

```yaml
date: 2026-09-08
plan: 2026-09-current
day: B                     # which plan day this fulfilled
duration_min: 52
rpe: 7
exercises:
  - name: squat
    sets: [{reps: 5, kg: 80}, {reps: 5, kg: 80}, {reps: 5, kg: 80}]
  - name: run
    sets: [{min: 20, km: 3.6}]
notes: "knee fine, felt strong"
```

## 5. Conversation flow

- **Onboarding (once):** Claude interviews you → writes `profile.yaml`, `catalogue.yaml`, first
  plan. Commits.
- **Session day:** you say "workout" (or the nag issue pinged you). `/workout` reads plan +
  last 4 weeks, runs `trainer next`, prints today's session with targets and one coaching line.
  During the session you dictate in your own words ("squat 80 five, five, five; last set ugly").
- **Logging:** `/log` turns the dictation into the yaml above, runs `trainer validate`, shows
  a 1-line confirmation, commits + pushes. Corrections are just another commit.
- **Weekly:** Monday the action opens an issue with stats + chart. You open Claude, say
  "review". `/review` proposes next week's changes (progression, deload, swaps for pain),
  waits for your yes, writes the plan, closes the issue.
- **Tone rules (in CLAUDE.md):** one-line answers by default, numbers over prose, never
  motivational filler, ask one question at a time, Hebrew if you start in Hebrew.

## 6. Progression logic (CLI, not Claude)

- Linear for main lifts: +2.5 kg when all target sets hit at RPE ≤ 8 two sessions running.
- Hold on miss; −10 % after 3 misses (auto-deload).
- Conditioning: +5 % time or distance per week, deload every 4th week.
- Streaks/adherence: sessions done ÷ sessions planned, per week, shown as a 12-week strip.
- All of this is a table in `plans/*.yaml` (`progression: linear|hold|custom`), so changing
  the rule is a file edit, not a code change.

## 8. Decisions I made for you (say no to any)

1. Files are YAML, not JSON or SQLite — human-readable in the GitHub UI, diffable.
2. CLI in .NET 8 — matches your toolchain and tests; `py` is the fallback if you want speed.
3. Voice = Claude app voice mode, no custom TTS/STT in phase 1.
4. Reminders = GitHub Issues opened by Actions (they hit your mail/phone with zero extra infra).
5. Private repo, no Pages, no public dashboard.
