# Personal Exercise Trainer — Plan

Owner: Tal. Date: 2026-09-08. Status: phases 0-1 built 2026-09-08; CLI (phase 2) next.

## 1. What it is

A trainer you talk to. Every day it asks what you did, records it, works out which muscle
groups are fresh, and plans the next day - re-planning whenever you did something else. Every byte of data lives as plain
files in a private GitHub repo (`talgiladi/personal-trainer`) — no database, no third-party
fitness service, fully greppable, fully yours.

The "brain" is Claude. The repo is the memory. A thin CLI does the arithmetic Claude should not
do by hand (volume, progression, streaks, charts). Voice is a front-end option, not a core part.

## 2. Facts (from Tal, 2026-09-08)

- Trains **every day**. Main targets: **strength + cardio**.
- Home only: dumbbells, bands, bodyweight. Cardio is HIIT / Tabata at home.
- Exercise names dictated in **English**.
- **No** body-weight or heart-rate tracking.
- "Speak with me" = conversational in the Claude app (desktop/mobile), voice via the app's
  voice mode. No custom speech stack.
- One user, private repo, no third-party fitness service.
- Units: kg, km, min. Timezone Asia/Jerusalem.
- This repo is standalone. It shares nothing with work repos - no global CLAUDE.md, no memory.

## 3. Architecture

```
 you (chat / voice)
      │
      ▼
 Claude (Claude Code or Claude app) ── reads CLAUDE.md + skills in the repo
      │            │
      │            └── runs `trainer` CLI for math/validation/charts
      ▼
 GitHub repo  (data/*.yaml, logs/*.md, plans/*.yaml)
      │
      └── GitHub Actions: validate on push, weekly summary, streak/nag reminders
```

Three components:

1. **Repo as the system of record** — all state is files; every workout is a commit. History is
   `git log`. Rollback is `git revert`.
2. **Claude as the trainer** — a `CLAUDE.md` persona + three skills (`/workout`, `/log`,
   `/review`). It talks, plans, and writes files. It never invents numbers: it calls the CLI.
3. **`trainer` CLI** (.NET 8 console, single-file publish; or `py` if you want it in an hour) —
   `validate`, `next`, `log`, `stats`, `chart`, `progress`. Deterministic, unit-tested.

Why not an app with a DB: you would build a UI nobody uses. Chat + files gets a working trainer
in a weekend and keeps every design decision reversible.

## 5. The daily loop (decided here in Claude Code, stored on GitHub)

1. Trainer asks **one** question: "What did you do yesterday?"
2. Logs exactly what was done - even if it was not the plan. `followed_plan: false`, no
   scolding; reality is the input, the old plan is discarded.
3. `tools/muscles.py` turns the logs into a muscle-group table: last worked, hours since,
   sets in 7 days, fresh / recovering / STALE. Committed as `state/muscles.md`.
4. Trainer picks the **next** session from that table (rules in `CLAUDE.md`): alternate
   strength / HIIT, STALE group first, fewest-sets group next, respect `recovery_hours` and
   `weekly_targets`, templates A-G as starting points, loads from the last two logs.
5. Writes `plans/next.yaml`, validates, commits `checkin: <date>`, pushes.
6. Replies with the next session, one line per exercise, one clause of reason.

`/workout` just shows `plans/next.yaml`; "shoulder hurts" / "no HIIT today" rewrites it.
`/review` stays weekly. Tone: one line, numbers, no filler, one question at a time.

## 6. Progression logic (CLI, not Claude)

- Linear for main lifts: +2.5 kg when all target sets hit at RPE ≤ 8 two sessions running.
- Hold on miss; −10 % after 3 misses (auto-deload).
- Conditioning: +5 % time or distance per week, deload every 4th week.
- Muscle-group recovery: 48 h legs/push/pull, 24 h core/cardio; STALE after 5 days.
- Weekly floors: legs 2, push 2, pull 2, core 3, cardio 3 per rolling 7 days.
- Streaks/adherence: sessions done per week, shown as a 12-week strip.
- All of this is a table in `plans/*.yaml` (`progression: linear|hold|custom`), so changing
  the rule is a file edit, not a code change.

## 8. Decisions I made for you (say no to any)

1. Files are YAML, not JSON or SQLite — human-readable in the GitHub UI, diffable.
2. CLI in .NET 8 — matches your toolchain and tests; `py` is the fallback if you want speed.
3. Voice = Claude app voice mode, no custom TTS/STT in phase 1.
4. Reminders = GitHub Issues opened by Actions (they hit your mail/phone with zero extra infra).
5. Private repo, no Pages, no public dashboard.
